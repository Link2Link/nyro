# Devin 单 Provider 混合账号池

状态：代码改进位于工作树，部署与真实账号验收需单独执行。[English](./devin-account-pool.md) · [领域术语](../../CONTEXT.md)

## 一、自动识别，允许混池

一个 Devin Provider 仍然是一个对外路由目标，但内部可以混合 **Pro、Team Full Seat 和 Max**。创建 Provider、添加账号时不再选择档位。

认证后的 `GetUserStatus` 成功后：

- 套餐名去首尾空格、忽略大小写，`max` / `devin max` 识别为 Max。
- 其他名称全部按 Pro 等价账号，包括 Pro、Team Full Seat、未知名称、空白及缺失名称。
- 查询失败或从未成功查询不是“套餐名称为空”：此时仍未识别，不能假装已有 1 份 Pro 容量。
- **Max 没有日额度，周容量为 10 份 Pro 周额度。**
- **非 Max：日容量 1 份 Pro 日额度，周容量 1 份 Pro 周额度。**

这是账号池采用的产品换算规则，不是上游返回的绝对 Token/ACU 限额。用量继续标为估算；相同 token 能去重，但未通过独立身份 RPC 审计不同 token 是否共享同一订阅。

```text
客户端 → 原有模型/Provider 路由
       → 账号资格、额度层级、优先级、会话粘性与轮询
       → 固定账号凭据快照 → Devin 原生转发
       → 更新该账号的配额、授权与健康状态
```

模型绑定、Provider 权重、官方地址、协议和代理策略保持共享。不创建隐藏 Provider，不把 OAuth token 塞进 API Key 池，不在并发请求间修改全局“当前账号”。

## 二、日/周额度换算

统一使用 **Pro 等价额度**，日与周分别计算：

| 账号类别 | 日容量 | 周容量 |
| --- | ---: | ---: |
| Pro / Team Full Seat / 非 Max | 1 | 1 |
| Max | 不适用，不计入 | 10 |

每个窗口中，`c_i` 是账号容量、`r_i` 是其剩余百分比：

```text
总容量         = Σ c_i
剩余额度       = Σ(c_i × r_i / 100)
已用额度       = 总容量 - 剩余额度
池剩余百分比   = 剩余额度 / 总容量 × 100%
池已用百分比   = 100% - 池剩余百分比
```

混合账号不能直接平均百分比；日额度只计算非 Max，周额度全部按容量加权。该统计是当前窗口快照，不是统一自然日累计消费，也不是 Token 数，日额度不能兑换周额度。

### 示例

| 账号 | 日剩余 | 周剩余 | 周容量 |
| --- | ---: | ---: | ---: |
| Pro A | 60% | 20% | 1 |
| Team Full Seat B | 30% | 60% | 1 |
| Max C | — | 50% | 10 |

- 日：总容量 2，剩余 `0.6 + 0.3 = 0.9`，**剩余 45%，已用 55%**。
- 周：总容量 12，剩余 `0.2 + 0.6 + 10 × 0.5 = 5.8`，**剩余 48.33%，已用 51.67%**。
- 周数据覆盖率为 **3/3 个账号**，不是 3/12。容量份数与账号数必须分开。
- 全 Max 池隐藏日额度；3 个 Max 的周总容量是 30 份 Pro 等价周额度。

### 统计成员、未知数据和重置

- 已启用且未断开/移除的账号参与容量统计，包括耗尽、冷却和需要重登的账号；暂时不可调度不缩小分母。
- 停用、断开、移除会同时改变容量和剩余小计，并单独显示原因，不伪装成上游消费或恢复。
- 已识别类型但缺少用量的账号仍贡献对应容量；该窗口完整百分比返回 null，直到获得观察。
- 未识别账号使 `capacity_complete = false`，`total_units` 只能表达已识别容量小计；完整已用/剩余总量和百分比均返回 null。不能在查询成功前把它猜成 Pro。
- 新增 `total_accounts` 作为窗口数据覆盖率和重置数量的分母；日窗口排除已知 Max，但可保留未识别账号占位。`known_accounts` 是观察数，不是容量份数。
- 查询失败保留最后成功快照并显示 stale。成功查询发现账号升降档时自动换算新容量，不再因与旧 Provider 档位不同而隔离。
- 保留每账号 reset。统一返回 `next_reset_at`、`next_reset_accounts` 和 `reset_mode = aligned | staggered | unknown`；一个账号重置不代表全池重置。
- 付费余额不混入套餐日/周容量。

两个 Pro 账号 A（日100%、周0%）、B（日0%、周100%）会让两条汇总条都剩50%，但没有可用套餐账号。因此额度条和可调度数量必须分开；若池内还有周额度健康的 Max，仍可由 Max 服务，因为 Max 没有日限制。

## 三、调度与安全边界

每次请求：

1. 排除停用、断开、鉴权失效、未识别、模型冷却/熔断和本请求已尝试的 `(Provider, account, model)`。
2. 套餐额度优先，其次未知用量，再次明确允许的付费余额。
3. 在当前层级按配置优先级选择，能保留有效会话绑定则保留。
4. 否则同级轮询；也可选 `fill_first`。
5. 提交前复核凭据版本和池策略，失败重选时根据最新状态排序，避免旧顺序提前选用付费余额。

Pro 看日+周，Max 只看周。缺少必需观察时属于未知，不假装完全可用。明确配额拒绝持续阻塞，只有更新、更完整的权威结果确认恢复才能解除；部分字段、时间到了都不够。

**周容量10倍只影响额度换算，不自动让 Max 获得10倍请求权重。** 外层 Provider 权重和内层轮询保持原规则。外层 `usage` 仍取真实可用代表账号评分，不把混合平均条和虚构共同 reset 送进单账号评分器。

默认池策略：

```json
{
  "account_pool": {
    "strategy": "round_robin",
    "session_affinity": true,
    "affinity_ttl_seconds": 3600,
    "max_account_attempts": 3,
    "reserve_policy": "disabled"
  }
}
```

不再有生效的 Provider `plan`。HTTP/Tauri 创建可以省略池策略，采用上述默认值；旧输入里的 `plan: pro|max` 仅为兼容而读取，运行时忽略，新响应和保存结果不再输出。

### 会话和失败切换

- 粘性按调用方、Provider 和明确会话 ID 隔离，prompt cache key 不是会话 ID。上游 session ID 包含账号命名空间。
- 绑定、冷却、健康按凭据代次隔离，旧 token 的迟到错误不能影响新授权。没有会话 ID 的请求正常选号。
- 只有明确的结构化执行前拒绝，且下游未提交时才可重试。裸403/429、提交后执行不明的超时、已经输出文本/工具或无法还原的账号私有 continuation，不允许自动重放。
- 任何 Connect Data frame 都算执行证据，包括缓存中的 tool/usage，以及与错误 trailer 同一个 chunk 的数据。
- 默认最多尝试3个不同账号，请求级最多8次上游生成并共享deadline；熔断跳过不消耗生成预算，也不能截掉后续健康账号。
- 配额恢复不清独立模型错误，鉴权失效需重登；同原因重复配额拒绝也递增 revision，防旧查询覆盖新证据。

## 四、登录、凭据与持久化

[核心账号管理](../../crates/nyro-core/src/admin/account_pool.rs) 负责创建、添加、重登、启停、移除和用量查询，HTTP/桌面入口只做适配；前端 DTO 不携带 token。

`provider_oauth_credentials` 是单一凭据来源，使用稳定本地 `account_id`、非唯一 `provider_id`、别名、启用、优先级、版本和账号状态。[数据库说明](../database/schema.md) 记录四类存储契约和迁移。

- 添加是追加，重登指定账号ID+版本，不覆盖兄弟账号。
- 登录 session 在服务端绑定 Provider/账号/版本/fence，不能在回调后任意改目标；单次消费、取消和过期校验保留。
- 单个请求固定 `(Provider, account, version, token)`。
- 断开清除密钥但保留tombstone和版本，旧登录回调、空槽并发绑定不能复活已退出账号。
- 用量发布比较凭据版本和原始状态；重复拒绝也改变revision。
- 读取旧usage时自动按实际snapshot识别，并忽略以前的Provider档位不匹配标记；鉴权失败和硬配额阻塞仍保留。
- 非Devin OAuth仍限制单账号。旧Provider-only修改操作及模型生成探测面对歧义时拒绝，不随机选择或删除账号；Provider连通性测试明确采用下述账号池语义。

## 五、界面与接口

创建显示“自动识别档位”，不再要求选择Pro/Max。设置只保留调度、粘性、尝试上限和付费余额策略。旧单账号启用混池不需要选档；启用前仍能走原重登流程。

```text
Devin · 混合                2个Pro等价账号 · 1个Max · 3个可用
日额度  已用55%    剩余45%       0.9 / 2 份Pro等价额度
        仅非Max账号
周额度  已用51.67% 剩余48.33%    5.8 / 12 份Pro等价额度
下次账号额度重置：...（1/3账号） [管理账号]
```

纯Max池没有日条；混池账号表中的Max日额度显示不适用。逐账号显示自动识别类型和最后成功观察时间。容量未完整识别、旧数据、实际可用性、余额兜底均明确提示；前端不重复计算后端聚合。

现有账号API和CAS请求兼容。`PoolQuotaWindow` 新增 `total_accounts`、`capacity_complete`，`total_units` 改为Pro等价加权容量；counts新增 `pro`、`max`、`unclassified`，旧 `plan_mismatch` 字段兼容保留为0。新保存/导出不再带旧Provider档位限制。

### 统一进度条与匀速使用预估

每个账号的日/周单元格复用其他供应商的已用百分比进度条、颜色和参考针：已用低于70%为绿，70%起橙，90%起红。明确标注已用和剩余；Max日额度是不适用，缺少观察显示未知，不画成已用0%。

单账号匀速参考为 `clamp(100 × (1 - (reset - now) / 窗口时长), 0, 100)`，日窗口24小时、周窗口7天。池级参考为 `Σ(账号容量 × 账号匀速参考) / Σ账号容量`，日按Pro=1且排除Max，周按Pro=1/Max=10，成员口径与后端容量一致。使用每账号自己的reset，不能把池内最近重置时间当成共同重置。

参考针每30秒由本地时钟更新，不额外查询上游；悬停说明为估算及容量加权。缺失/无效reset、类型未识别、用量不完整、容量不一致时隐藏总体参考针；实际用量仍由后端给出，不重新计算。耗尽/鉴权失效账号仍在分母，时间经过不代表额度已恢复或可以调度。

### 每账号网关历史用量

每个账号的操作按钮下方增加紧凑统计块，分别显示 **全部记录** 与 **本周** 的总 Token 和等价 API 估算金额。本周从浏览器本地时区的周一 00:00 开始，不跟随上游周额度重置。按精确 Provider 下的 `route_decision.account.account_id` 归属统计保留的上游尝试（包括重试和失败）；修改别名、优先级、启停和刷新凭据不会重置归属。旧日志缺少账号 ID 时不猜测或分摊。输入 Token 已含缓存读取，总 Token 仅为输入加输出。

`GET /api/v1/providers/:id/accounts/usage-stats?period_start=<毫秒时间戳>`（桌面命令 `get_provider_account_usage_stats`）为每个当前账号返回 `account_id`、`all_time`、`period`。两个窗口均包含 `total_tokens`、`request_count`、按原始币种分组的 `equivalent_costs`、`unpriced_request_count`。窗口截止到服务端采集的当前时间；客户端传入的 `period_start` 必须介于零和当前时间之间。仅展开的管理面板批量查询所有账号，每分钟刷新；该接口不查询上游，也不影响调度。

金额复用当前手工价/目录价，并非订阅扣费或历史账单；缺价显示不可用，部分估算会标注，币种不直接混加。这是 **保留日志累计** 而非永久台账：删除/清理日志会改变两个窗口，缺失的上游用量无法还原。SQLite、PostgreSQL、MySQL 复用现有日志，不改数据库结构；纯内存模式没有保留日志用量。

### Provider 连通性测试

`test_provider` 使用不生成聊天的认证状态 RPC，检查全部已启用 Devin 账号；单次测试最多并发4个，每账号超时15秒。一个账号失败不妨碍检查其他账号，**任一账号通过即 Provider 连通成功**；停用账号跳过，无已启用账号或全部失败时整体失败。

返回结果新增可选 `accounts` 明细，只包含账号ID、安全别名、成功与否、耗时、脱敏错误、跳过原因和观察时间，顺序与账号池一致。测试期间被重登、停用或移除的凭据记为跳过，不能作为当前成功。旧客户端没有此字段仍兼容。

前端逐账号记录通过/失败/跳过，再显示池汇总；后续获取模型目录失败也保留账号测试明细。连通测试不改变账号配额或鉴权失效状态，**不保证仍有额度或具备某模型权限**。Devin 模型发现只是静态建议列表，不依赖选取某个账号；实际模型生成测试仍是独立操作。

## 六、兼容与部署限制

- 本次混池修订只改变策略和JSON语义，不改SQL表结构。账号ID、凭据、模型绑定和策略偏好保留；旧plan字段读时忽略，旧快照自动规范化，无需因为混池升级而重新登录。
- 初次从单账号表升级到多账号表仍须备份真实数据库并停止旧二进制；配置JSON不备份OAuth密钥。
- **一个账号池数据库只运行一个Gateway实例。** session/fence与调度协调是进程内机制，不支持多活管理写入。
- 余额兜底默认关闭；它不是上游账单硬限额，一次请求仍可能触发上游自动overage。
- 单账号并发上限、分布式lease、配额加权选号、身份审计、仅复制池配置专用动作不属于本次修订。
- 正式部署和真实Devin登录/聊天需单独验收；本地测试不操作生产数据。

## 七、验收重点

- 新建无需plan；旧Pro/Max配置规范化后不限制混池。
- Pro、Team Full Seat、Max共存；2个Pro等价+1个Max周总容量12，示例加权计算准确。
- Max日字段伪影被去掉；纯Max隐藏日；未知类型或窗口不能产生假完整容量。
- 升降档刷新自动重新加权，同时保留授权/配额版本保护；失败/部分观察不清已知阻塞。
- 优先级、轮询、粘性、余额次序、安全重试、跨模型fallback、旧登录均不回归。
- core/server/desktop检查与前端类型、聚焦测试、生产构建验证同一接口契约。
