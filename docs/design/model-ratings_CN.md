# 供应商模型评分

[English](model-ratings.md)

## 目标

Nyro 为每个精确的 **`供应商 ID + 上游模型名`** 保存一个人工综合能力分。
分数为 **0–100 整数**，只表达管理员的相对能力评价，不是客观 IQ、评测结果、
成功概率或倍数尺度；不包含速度、价格、可用性。

评分管理提供逐项编辑、持久化、跨供应商比较、供应商复制和配置备份。
每个供应商模型的评分档案包含一个可空的**通用分（common）**及五个可选覆盖分：
**low / medium / high / xhigh / max**。**性能**页按可信完成请求的观测 TPS
与有效能力评分绘图。**评分仍不影响现有路由。**
绘图或路由必须单独处理未评分，不能把缺省状态转换成某个数值。

## 评分状态与模型标识

| 状态 | 表示 | 含义 |
|---|---|---|
| 已评分 | `status: "rated"`，整数分数及时间 | 有已保存评价，0 分也是有效评分 |
| 未评分 | `status: "unrated"`，`score: null`，`updated_at: null` | 查询成功，但没有评分记录 |
| 未知/错误 | 请求失败，界面明确报错 | 无法确定评分，不能冒充未评分 |

数据库只保存显式评分的范围；清除就是删除该范围的记录，`null` 表示缺省而非 0。
每档按**档位覆盖分 → 通用分 → 未评分**解析；覆盖分即使与通用分相等（包括 0）
也保留为显式覆盖。清除通用分不影响覆盖分，清除覆盖分恢复继承。
状态由记录是否存在派生。供应商以 ID 标识，而非名称或 vendor。
多个路由引用同一供应商模型时共享档案；删除或重建路由映射不会删除评分。

评分 API 精确保留模型名的大小写、首尾空格、Unicode、命名空间和斜杠，不做
trim、模糊匹配、别名归并或 Unicode 归一化。名称不可全空白、不可含 NUL，
上限 1024 UTF-8 字节；超限报错而非截断。上游目录到 Nyro 模型名的转换，仍由现有
供应商协议解析边界负责。

每条 `(provider_id, upstream_model, effort)` 记录仅保存分数和更新时间；
`effort` 为 `common` 或五个档位之一，不增加备注、多维能力、置信度或历史。
新增/变更的档案分数使用服务端 UTC RFC3339 毫秒时间，未变更范围保留原时间；
旧单项保存重新确认通用分时更新时间。并发编辑采用最后成功写入者生效。
旧版单一评分迁移到 `common`，原分数和时间不变。

性能档位 **low** 同时包含实际出站的 `minimal` 和 `low`；`medium`、`high`、
`xhigh`、`max` 分别统计。预算制、关闭、其他、未知及未指定 effort 不猜测归档，
仅在完成状态与 TPS 均可信时参与混合统计。

## 管理界面

- **可用模型**页显示分数或明确的“未评分”，支持逐个编辑。
- **模型评分**页（`/model-ratings`）以平铺列表跨供应商管理，可搜索、按供应商/
  评分状态/分数范围筛选，按分数/名称/更新时间排序及分页。
- 列表为成功目录、已知路由目标、已保存评分三者的并集。禁用供应商和已不在目录中
  的评分仍可管理。
- 默认分数降序；无论升序或降序，未评分始终置后。分数范围只包含已评分记录；
  同分按稳定的身份顺序排列。
- 同一个模型弹窗编辑通用分与全部五档覆盖，显示显式/继承/未评分状态；一次“保存”
  **原子提交整个档案**。校验或存储失败时所有范围保持原状，取消丢弃整个草稿。
- 输入必须是整数，不取整、不夹到范围内。空值不等于 0，清除/取消覆盖由明确操作表达；
  与通用分相等的覆盖不会被自动折叠。
- 评分请求失败时显示错误与重试，不能展示虚假的未评分数量。目录请求失败时说明
  列表可能不完整，但不妨碍编辑已保存评分。
- 只有成功目录中未出现的模型才标记“目录缺失”；禁用或加载失败显示“目录未知”。

评分管理页通过 `require_catalog=true` 获取目录，明确报告网络、HTTP、JSON 或
目录结构错误，而不是使用旧逻辑静默返回空目录/静态兜底。其他目录消费者保留
原有行为。保存和清除评分本身不查询上游。

## 性能图表

**性能**页（`/performance`）位于**统计**下方、**扩展**上方，使用独立的
`/api/v1/model-performance` 快照，不查询上游目录或发送测速请求。
**新聚合口径仅用于性能页**；`get_model_usage_stats` 等旧用量 API 保持原样。

### 评分与样本分组

- **没有显式覆盖**时，仅进入混合图，以通用分配混合 TPS。**任意一档有覆盖**时，
  切换为五档图，每档以有效评分配**同档 TPS**，绝不借用混合或其他档位的样本。
  与通用分相等的覆盖同样触发切换。未评分或无有效 TPS 的档位不画点。
- 每个精确供应商模型、每个分组独立选取**过去 7 天内最近 10 条已完成请求**，再对
  其中有效的逐请求 TPS 取算术平均。按完成时间倒序、请求 ID 倒序稳定排序。
  这十条中的无效 TPS 不会由更旧的第十一条补位。
- 仅纳入具有可信完成元数据且上游/客户端 HTTP 状态成功的请求。失败、取消、超时、
  截断、token 上限及完成状态未知的尝试，在最近十条选取前排除。
- TPS 为输出 token 除以实测上游生成耗时，不是总 token 加权平均。
  缓冲响应使用完整上游耗时；流式减去首块耗时，但生成阶段短于 50 ms 或首块耗时
  达上游耗时 80% 时使用完整耗时。缺失、非有限、非正数或矛盾的时间/token 不补 0。
- **1 个有效样本即可画点，少于 3 个有效样本用空心点**。计数区分选中的完成请求数与
  有效 TPS 样本数；样本时间来自有效样本，而非最近任意调用。未归档的完成请求仅用于
  混合统计；不可信历史请求数另行显示。

### 完成状态与 effort 来源

Effort 在每次尝试的**最终上游出站请求、全部改写完成之后**采集，包括路由 max 覆盖
和供应商方言映射。客户端日志字段 `reasoning_effort` 不能作为出站证据缺失时的兜底。
即使关闭载荷日志，也保存这些标量元数据。

每次尝试在响应 Body 边界观察完成状态，**先完成观察，再持久化日志**。仅收到成功的
协议终止事件还不够：Body 交付被取消或出错时不算完成。“完成”指网关观察到 Body EOS
并有可信的成功终止结果，**不是客户端 ACK**，也不证明客户端应用已经消费响应。

升级前的全部日志保持 `request_completion = 'unknown'`：旧状态码、用量与载荷不能
证明 Body 交付完成。可以对过去 7 天内保留的上游请求体分批恢复**出站 effort**，
但不能使用客户端兜底，也不能恢复历史完成状态。因此升级后的图表需要新的可信样本，
不能拿旧日志中看似成功的请求填图。

完成证据解析采取保守策略：单个缓冲响应或 SSE 事件超过 1 MiB、原始压缩字节无法直接解析、
终止原因未知，或缺少协议必需的结束标记时，不确认成功完成。请求本身仍沿用原代理处理，
但不会进入新性能样本；这可能造成某些正常请求没有图表数据，不代表自动判断其模型性能为 0。

### 图表交互

- 横轴固定 **0–100**，显式 0 分正常绘制；纵轴从 0 开始，初始上限 **200 TPS**，
  超出时按 **50 TPS** 步长扩展。
- 按供应商稳定配色，点上使用紧凑编号；侧栏列出完整供应商/模型/档位身份、评分来源、
  TPS、计数及时间。编号按完整快照分配，筛选时保持不变。
- 精确重合点分组，附近候选列表支持密集点选择，实际坐标**不抖动、不偏移**。
  鼠标、键盘、触屏均可选择并固定高亮，图中点与侧栏联动。
- 按供应商/文本筛选但不重新编号；保留评分的禁用供应商仍可显示，小屏可横向滚动。
- 刷新整体替换快照（评分、统一 `as_of`/窗口及所有分组）。缺失 TPS、加载与失败
  明确显示，不伪造 0 点；响应标记某模型不可用时，其他有效模型仍可显示。

性能是受请求规模、上游负载及推理设置影响的观测值，以当前人工评分配近期调用，
不是受控评测，也不意味着各 effort 档位的工作负载相同。

## 管理接口

所有接口沿用现有 Admin API 认证，不暴露到代理侧的公共模型元数据。
桌面 IPC 调用相同的核心服务。

| HTTP | 用途 |
|---|---|
| `GET /api/v1/provider-model-rating-profiles` | 已保存档案，含禁用/目录缺失；可选 `provider_id` 筛选 |
| `GET /api/v1/providers/:id/model-rating-profile?model=…` | 完整档案、各档有效分/来源及显示模式 |
| `PUT /api/v1/providers/:id/model-rating-profile?model=…` | 原子替换通用分和全部五档覆盖 |
| `GET /api/v1/model-performance` | 一个 `as_of`、`window_start` 及 `models` 快照；可选 `provider_id` 筛选 |
| `GET /api/v1/provider-model-ratings` | 旧接口仅列出 **common**；可选 `provider_id` 筛选 |
| `GET /api/v1/providers/:id/model-rating?model=…` | 旧接口查询通用分的明确已评分/未评分状态 |
| `PUT /api/v1/providers/:id/model-rating?model=…` | 旧接口仅保存通用分 `{ "score": 85 }` |
| `DELETE /api/v1/providers/:id/model-rating?model=…` | 仅清除通用分，保留所有覆盖，返回 `{ "ok": true }` |

档案 PUT 必须包含可空通用分及**全部五个**可空覆盖分，含未改动/未设置项，
不是局部 patch：

```json
{
  "common": 80,
  "overrides": { "low": null, "medium": 0, "high": 80, "xhigh": null, "max": 95 }
}
```

这里 medium 为显式 0 分，high 虽与通用分相等仍是覆盖。缺键、多余字段/档位、
非整数及超范围分数会在任何写入之前拒绝；全 null 原子清除整个档案。
返回档案使用可空 `{score, updated_at}` 值、`effective` 各档状态及 `source`
（`override`/`common`/`unrated`）、`score_updated_at`，并有 `display_mode`
（`common`/`per_effort`）。

性能快照每个模型包含 `profile`、`mixed`、`tiers`、`unclassified_count`、
`untrusted_count`、可用性 `status`（不可用时带 `error`）。每个混合/档位分组含
`selected_request_count`、`valid_tps_count`、可空 `average_tps`、
`first_sample_at`、`last_sample_at`。快照/样本时间为 Unix 毫秒。
没有样本是合法空分组，不是统计失败。

模型名作为查询参数需要 URL 编码，尤其 `/`、`+`、`#` 和空格。
列表、查询、保存沿用 `{ "data": ... }` 响应封装，例如：

```json
{
  "data": {
    "provider_id": "provider-id",
    "upstream_model": "vendor/model-x",
    "status": "unrated",
    "score": null,
    "updated_at": null
  }
}
```

旧接口已评分时 `status` 为 `rated`，`score` 是包含 0 在内的整数，时间非空。
旧 PUT 拒绝缺省/null/字符串/小数/超范围评分，以及客户端设置更新时间等多余字段。
有效供应商下重复清除幂等成功。评分错误使用 JSON `{ "error": "..." }`，状态码
为 400 输入错误、404 供应商不存在、501 后端不支持、500 内部失败；存储错误
不能转换成空列表成功。

列表枚举的是**已保存评分**，不是全部未评分模型。未来消费者必须在评分读取成功后
与自己的候选模型集合关联，或查询单项明确状态。目录不可用时，无法统计尚未发现
的未评分模型。

## 生命周期与备份

| 事件 | 评分处理 |
|---|---|
| 目录刷新、临时下架、探测失败 | 保留分数和时间 |
| 禁用供应商、更换地址/账号/渠道 | 保留，由管理员按需重新评价 |
| 删除路由映射 | 保留 |
| 同一供应商下精确同名模型重新出现 | 复用原分 |
| 新名称或别名出现 | 不自动继承 |
| 清除范围 / 整个档案 | 只删除精确组合的该范围 / 全部六个范围 |
| 删除供应商 | 在事务中删除该供应商全部范围评分 |
| 复制供应商 | 全部通用/覆盖分数与原时间复制到新 ID，之后各自独立 |
| 导出配置 | 在所属供应商下写入带 `effort` 的 `model_ratings`，含全部范围及禁用/目录缺失记录 |
| 导入新供应商 | 绑定新 ID，保留原评价时刻，格式统一为 UTC 毫秒 |
| 导入时供应商同名已存在 | 供应商及其评分整体跳过，不覆盖当前评分 |

导出是现有版本 2 的兼容字段扩展，无评分字段的旧备份仍可导入；旧评分记录缺省
`effort` 时按 `common` 导入。不能指望旧版 Nyro 完整保留新增评分范围。

导入修改配置前先校验全部评分、标识、时间、effort 范围与重复精确
`(upstream_model, effort)` 键。某供应商评分恢复失败时
回滚刚创建的供应商，但不全局回滚先前已成功导入的其他供应商；错误反馈说明
部分完成情况。复制评分失败同样报错并回滚新供应商，不返回无评分的“成功副本”。

## 架构与验证

`ProviderModelRatingStore` 独立于路由快照、后端权重和第三方模型能力目录。
SQLite、PostgreSQL、MySQL 均持久化评分；YAML/MemoryStorage 保持现有只读/
不支持边界，不把重启即丢失的操作伪装成持久化保存。

单独修改评分不改变 `config_epoch`，不重载路由缓存或刷新配额。两处 UI 共享
经过校验的评分查询，修改后失效缓存，评分刷新与目录刷新独立。
数据库结构与临时库生成参考 SQL 的方法见[数据库文档](../database/schema.md)。

针对性验证命令：

```bash
cargo test -p nyro-core --test provider_model_ratings
cargo test -p nyro-core --test storage_provider_model_ratings
cargo test -p nyro-core --test storage_effort_performance
cargo test -p nyro-server --no-default-features rating_
cargo check -p nyro-core
cargo check -p nyro-desktop
```

WebUI 在 `webui/` 下执行 lint/build。轻量 UI helper 测试不需要额外测试框架：

```bash
# 在 webui/ 下执行
test_dir=$(mktemp -d /tmp/nyro-rating-tests.XXXXXX)
./node_modules/.bin/tsc src/lib/model-ratings.test.ts --outDir "$test_dir" \
  --module commonjs --moduleResolution node --target es2020 \
  --esModuleInterop --skipLibCheck
node --test "$test_dir/model-ratings.test.js"
```

存储测试通过显式的临时库变量开启
PostgreSQL/MySQL 实测；跳过不等于该后端验证通过。`tests/webui/` 的 Node/CDP
冒烟测试只使用隔离的临时服务，验证真实浏览器操作，不连接现有部署。
